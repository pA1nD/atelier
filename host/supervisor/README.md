# `host/supervisor/` — the app supervisor (PLAN §4.9 step 2, DESIGN §4.1 / §6.1)

One table of app instances on one computer. Per instance TWO slots (DESIGN §10.3): `dev` — the agent's
tree, one watcher, hot reload, the dev shell's — and `prod` — the released commit's export, the protocol
port's; each with its own worker (or none — resumed lazily from its pointer), one revision counter shared.
Every other lane reaches it through the surface in `index.mjs`; it reaches them through the injected
collaborators (`spawn`, `proxy`, `jail`, `install`, `hook`, `report`, `registrar`, `onSwap`, `onDevSwap`).

## Interfaces (DESIGN §4.1 terms)

To the **workers** lane (injected, never imported):
- `spawn({os, spec, onControl, onExit, readyTimeoutMs, lockSocket})` → `Promise<{pid, sock, kill(signal), stop(drainMs)}>`, rejecting `{error:'no-ready'|'spawn-eagain'|'load-failed', msg}`. `spec` is the §4.1 `WorkerSpec`; `spec.sock` is **per slot and rev** (`<sockDir>/w-<slot>-<rev>.sock`): load-beside needs the new dev worker bound while the old one serves, a proxy's keep-alive pool is keyed by socket path, and dev/prod/rehearsal never share a name (`lockSocket:false` for the rehearsal worker — the smoke step dials it as the worker uid). Control messages the supervisor consumes: `ready` (`resources`, `teardown`), `load-failed` (`code`, `message`, `file/line/col` in bundle coordinates — mapped back through the rev's source map), `suspendable`, `error` → `report('backend')`, `http5xx` → `report('http')`, `broadcast` → `onBroadcast(appRow, event)`.
- `hook({os, spec, cmd, cwd, extra, hostEnv, timeoutMs, log})` → `{ok, code, signal, ms, output, error?}` (worker/hook.mjs `runHook`, row K): the app's `deploy`/`test`/`smoke` command as the worker uid.
- `proxy({sock, req, res, user, bodyCap, timeoutMs})` → `Promise<{status, …}>`.
- `jail` (optional): `{jailPlan, applyJail, claimRoundTrip}` — applied before every spawn and at claim. Without it the supervisor creates `data/<inst>`, `tmp/<inst>`, the socket dir itself (local mode).
- `install` (optional): `installDeps({os, dirfd, spec, log, dest?})` — run on a root `package.json`/lockfile change (dev; success → rebuild) and, with `dest`, into the prod export at a deploy. Without it the change is a plain rebuild and the export copies the dev tree's `node_modules`.

To the **errors** lane: `report(kind, instance, rev, detail)` with `kind ∈ build|backend|http|worker`; `detail = {message, hint?, file?, line?, col?, stack?, sample?}`; the `hint` of every build failure is `formatHint(problem)` = `file:line:col message — fix`. `onSwap(instance, rev)` after every swap (the collector's `setRunning`, the events lane's invalidate).

To the **protocol-server** lane: `apps()` (rows with `rev`/`state` = prod's, `deployed_rev`, `prod_rev`, `dev_rev`, `prod_state`, `dev_state`), `workers()` (every slot's worker, `key` + `slot`), `resolve(company, slug)`, `handle(row, req, res, user, {slot})`, `asset(row, rel, {rev, slot})`, `rebuild`, `stop` (the install hold), `kill(instance, why, slot)`, `teardown`, `boot`, `scan`, `deploy(instance, {message, commit, noBackup, by, onStep})`, `restore(instance, id, {by, onStep})`, `releases(instance)`, `backups(instance)`, `onConfigStamp(instance, updated)`.

From the **registrar**: `claim({slug, meta, dir})` → `{instance, uid, …} | {refused}` (also called on the first scan for every boot row — the re-claim), `unlink(instance)` when a folder vanishes, `served(instance)` per proxied PROD request, `reconcile(rows)` after a scan, `company`, `origin`, optional `appConfig(instance)` → the OR14 env, `release(row)` → the spine's release door (never throws), `apps()` (the `deployed_rev` the register reply carried — the boot announce's anchor).

`log` is the agent.log writer: a function `(line) => void` or an object with `.write(line)`. Lines: `[<slug>] rev N LIVE (dev) in <ms> ms` · `rev N LIVE (prod) commit <c12> in <ms> ms` · `rev N FAILED (dev) <hint>` · `STOPPED` (` (dev)`) · `RESUMED <ms> ms` · `KILLED <why>` · `deploy <c12> "<msg>": <step> ok|FAILED <ms> ms` · `deploy <c12> RED|FAILED at <step>: …` · `adopt: …` · `config release: …` · `restore <id> done in <ms> ms` (agentlog prefixes the ISO time).

## What the Linux drill (host/drill, §8.2) must still prove for this lane

1. Reads inside a `1000:<uid> 2750` app folder succeed with the gid held and fail without it: watch registration, fingerprint walks, `module.json`, static assets, the esbuild plugin's reads (the Go service itself never touches the folder).
2. inotify budget ≤ 2 k watches over the 5 corpus apps after `npm install`; a 16 384-event burst → one build after quiet; `watch error` re-registration.
3. Rev dirs land `0:<uid> 0750` / files `0640` under the host's umask 077 (chmod-then-chown on root-owned inodes), `last-good/<inst>` EACCES to uid 1000, readable by the worker uid.
4. `git commit` as uid 1000 with cleared groups in a `2750 1000:<uid>` folder (row G).
5. The real `worker/runtime.mjs`: READY `resources` semantics (idle-stop decisions), MOUNT-ERROR/LOAD-ERROR `file/line/col` in bundle coordinates → source-mapped hints, `stop(drainMs)` with the process-group SIGKILL.
6. Socket dir `0:<uid> 0730` with per-rev socket names; `afterReady` chown on `spec.sock`.
7. Save → LIVE p50 ≤ 350 ms / max ≤ 1.1 s on the corpus apps in a pod (g4), one-sheet CSS ≤ 50 ms cold for the median app (b5).

Open (not built here): `spawn-eagain` is reported and the rev dir removed, with no automatic retry until the next save; `?rev=N` window pruning is timer-based (10 min after a swap; everything but `current` pruned at boot).
